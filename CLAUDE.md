# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Working rule

**Tests first, then implementation** (owner rule, 2026-10-01). Before writing the code for a feature or a fix, write the test that proves it; then implement until it passes.

- **Database changes:** add the new `PASS N` block to `supabase/tests/rls_smoke_test.sql` **before** writing the migration, then write the migration to make it pass. The owner runs that file in the SQL editor, so the test and the migration are handed over together.
- **Client logic** (money math, selectors, filters, parsers): write the check against the real module first, run it and watch it fail for the expected reason, then implement. There is no unit-test runner (only `typecheck` / `lint`), so until one is added the check is a Node fixture that imports the real file.
- **Bug fixes:** first a test that reproduces the bug, then the fix.
- **Not testable up front** (pure layout / visual work): say so before starting and verify in the browser afterwards — never skip the test silently.

## PilotGarage

One mobile-first PWA serving two related auto businesses: **PilotGarage** (`SERVIS` — auto service) and **Arabam.com** (`GALERI` — dealership). Yönetici picks/switches the active business in-app; all operational data is business-scoped.

**Status:** Architecture phase complete. See [`ARCHITECTURE.md`](ARCHITECTURE.md) for the canonical design. The pixel-level design reference lives in `design/` (`Auth.dc.html` + README) — follow it for ~90% of the UI; it is a spec, never imported/executed.

### Critical conventions

- **Stack:** Vite + React 19 + TS + Tailwind v4 + Radix primitives, React Router v8 (`basename /PilotGarage`), TanStack Query v5, Supabase (EU/Frankfurt), GitHub Pages. **Latest stable versions, resolved at scaffold time.**
- **Quality bar is zero mistakes** — especially finance and RBAC. Money/role invariants live in Postgres (constraints, `SECURITY DEFINER` RPCs, RLS), never client-only.
- **Onay gate:** every money entry (`MANUEL`, `KAYIT`, `CARI_HESAP`, `SABIT_GIDER`, recurring) is born `BEKLIYOR` and affects the kasa only after Yönetici/Muhasebe approves via RPC. **Exceptions:** maaş (`PERSONEL`/`MAAS`) işlemler are born `ONAYLANDI` via `pay_maas` + the cron — **avans and prim lost this exception in 045 (2026-07-21)** and now go through Onay like everything else, and the cron creates sabit giderler (016) **and tekrar-kural işlemleri** (019) born `ONAYLANDI` — all hit the kasa immediately, no Onay (recurring entries were approved once at setup). Cari-targeted rules still produce `YOK` hareketler needing yansıt + Onay. Balance is always a view over `ONAYLANDI` rows — never a stored number. Approved/rejected rows are immutable; corrections are counter-entries. İşlemler carry `odeme_yontemi` (`NAKIT`|`KREDI_KARTI`|`HAVALE` since 023, nullable): not asked on kayıt screens — `KAYIT`-sourced işlemler **require** it at Onay (`approve_islem(id, yöntem, komisyon)` refuses otherwise); manual entries set it in Gelir/Gider Ekle. Since **054 every payment path carries one**, and the rule is that the yöntem lives on the **definition**, never on the approved row: `business_members.odeme_yontemi` (maaş, elle + cron), `sabit_giderler.odeme_yontemi` (cron copies each period), `cari_hareketler.odeme_yontemi` (yansıtınca kopyalanır), avans/prim at creation. A NULL yöntem still moves the kasa total but lands in **no** bucket — that is why Nakit+KK+Havale can read less than Toplam on pre-054 rows.
- **Roles:** `YONETICI` (everything, both businesses), `MUHASEBE` (**Yönetici minus role control ve minus Onay** — full management + finance, but cannot approve/reject işlemler or kayıt silme (044, 2026-07-20), cannot see/decide İstekler (046), cannot write İşletme Ayarları — businesses update + kategoriler yazma (047, 2026-07-21) — cannot see salary amounts or set/pay/delete/restore maaş (063, 2026-09-13; DB refuses the writes, amounts are hidden in the UI only) — and cannot change user roles/status/business access or approve signups; business-scoped), `PERSONEL` (kayıt only). Open signup gated: new users are `PENDING` with `role = NULL` → **zero rows via RLS** until Yönetici assigns role + business. The NULL-role case must be explicitly tested.
- **Money math:** `NUMERIC(12,2)` server-side; integer kuruş client-side; one shared `formatTL` (tr-TR). Never float arithmetic.
- **PWA is first-class:** installable iOS/Android, offline app shell, `registerType: 'prompt'` (no auto-reload mid-form), safe-area bottom nav. No offline writes / no cached finance data in MVP.
- **GitHub Pages SPA:** `public/404.html` + restore script from day one; keepalive workflow every 6 days (2nd free-tier Supabase project alongside HomeGuru).
- **Timezone:** cron at `21:05 UTC` = 00:05 Istanbul; `odeme_gunu` capped at 28.
